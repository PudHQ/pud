# Second mathematics review of *The Software Engineer’s Introduction to Formal Verification*

The four bounds, the undo law on arbitrary integer coordinates, the list induction and the four-turn calculation hold up. The worked exercises give the claimed results, including the two-element array that exposes the wrong subscript. The main correction concerns what the checked types can tell us about an image.

## Findings in the second edition

**Chapter 5, “Keep the bounds with the cell,” p. 13.** “That particular board” suggests the type records which image supplied the pixel. Two unrelated four-by-three images accept exactly the same `Cell 4 3` value. Say that the proof ties the coordinates to these dimensions. The type contains neither an image identifier nor a pixel value. [Lean companion](proofs/Turn.lean)

**Chapter 1, “Who gets to choose first?”, p. 4.** The argument against `∃ y, ∀ x, y > x` is sound. The sentence introducing “a counterexample” can obscure the choice that makes it work. A fixed test at `x = 7` leaves `y = 8` alive. Write “For each proposed `y`, choose `x = y`.” That rule defeats every candidate.

**Chapter 7, “One more finished slot,” p. 22.** Two small steps are implicit in “establishes all three invariants.” Slots to the left of `i` keep their already-correct values because only slot `i` was written. The guard `i < a.Length` gives `i + 1 ≤ a.Length` because indices are integers. Both facts belong in the preservation argument. [Dafny companion](proofs/Turn.dfy)

## Checks on the replacement examples

**Pixel raster, chapters 2, 7 and 10.** In row-first array notation the pixel-value promise is `output[x][h - 1 - y] = input[y][x]` for every valid source coordinate. The companion loop keeps each sample in its original array slot and transforms the coordinates stored there. A two-by-two raster shows the distinction. In rows `A B / C D`, copying A straight to its clockwise destination overwrites B before a row-by-row scan has read it. A separate output buffer yields `C A / D B`. The point bijection supplies every output address exactly once. Preserving its pixel value is a further implementation obligation.

**Binary-search midpoint, chapter 4.** Use Java’s signed 32-bit `int`. With inclusive bounds `lo = hi = 2³⁰`, the addition wraps to `−2³¹`, so `(lo + hi) / 2` returns `−2³⁰`. Searching for the last index in `0…2³⁰` reaches this state. For `0 ≤ lo ≤ hi ≤ 2³¹ − 1`, the difference `hi - lo` fits, and adding half of it to `lo` stays at most `hi`. Those two bounds justify `lo + (hi - lo) / 2` on the machine. [Original bug report](https://research.google/blog/extra-extra-read-all-about-it-nearly-all-binary-searches-and-mergesorts-are-broken/) · [Java integer addition](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.18.2)

**Bank transfer, chapter 9.** Conservation assumes each update affects its intended account. Debit 30 from a balance of 100 and credit a missing recipient. PostgreSQL accepts an update that matches zero rows, so a careless transaction can commit a total of 70. Require one affected row on each side and roll back otherwise. Even a successful transfer from `(100, 0)` to `(70, 30)` can fool a reader. Under Read Committed, separate queries can see the old 100 and the new 30. A single query reading both accounts sees a consistent snapshot. [PostgreSQL transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) · [Update counts](https://www.postgresql.org/docs/current/sql-update.html#SQL-UPDATE-OUTPUTS) · [Read Committed](https://www.postgresql.org/docs/current/transaction-iso.html#XACT-READ-COMMITTED)

**The lower bound for `git bisect`, chapter 10.** Fix a linear history and a repeatable yes/no test that changes once from good to bad. Count possible *first bad commits*. In `G — a — b — c — d — B`, the known-good endpoint is excluded and the known-bad endpoint remains a candidate. Five possibilities need five distinguishable outcomes. Two tests give at most four, so every strategy using only those answers needs a third test on some history. For `m` candidates the worst-case lower bound is the smallest `k` with `2ᵏ ≥ m`. Balanced bisection attains it. Adjacent known endpoints need zero additional tests. [Git bisect manual](https://git-scm.com/docs/git-bisect)

## Final manuscript

The rewrite resolves the quantifier, image-identity and loop-invariant findings. Its raster specification follows a byte from its source row and column into fresh output storage. All four figures agree with the text. The transfer example distinguishes a missing recipient from a reader combining balances seen on opposite sides of one commit. The descriptions of Cedar, CompCert and IronFleet match the guarantees in their primary sources.
